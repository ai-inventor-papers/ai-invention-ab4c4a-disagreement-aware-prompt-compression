# Q4: Leave-one-sentence-out (LOO) ablation as ground truth

## 4a. ContextCite ablation design vs. exact LOO

**ContextCite (2409.00729)** fits a **sparse linear surrogate** to the logit-scaled probability of
a fixed response under random context ablations, rather than doing exact LOO:

> "we find that it is possible to learn a linear surrogate model that (1) faithfully models the
> language model's behavior and (2) can be efficiently estimated using a small number of
> additional inference passes. The weights of this surrogate model can be directly treated as
> attribution scores." (Introduction)

Ablation mechanics: sources (e.g. sentences) are removed by token deletion, `ABLATE(C, v)` for
binary vector v; the fitted target is **logit-scaled probability**: "Predict logit-scaled
probabilities: Fitting a regression model to predict probabilities directly might be problematic
because probabilities are bounded in [0, 1]. The logit function... is a mapping from [0, 1] to
(−∞, ∞), making logit-probability..." (§3). The regression is regularized with **LASSO**: "we
induce sparsity in the surrogate model via LASSO [Tib94]. As we illustrate in Figure 3b, this
enables learning a faithful linear surrogate model even with a small number of ablations. For
example, the surrogate model in Figure 2 uses **just 32 ablations** even though the context
comprises 98 sources (in this case, sentences)." Ablation vectors are sampled uniformly at random
over subsets: "we sample ablation vectors uniformly from the set of possible subsets of context
sources." **Number of ablations tested**: their sensitivity sweep runs 32/64/128/256/512 ablations
(Figure 3b caption: "32 64 128 256 512 / Number of ablations... Average RMSE"), confirming ~32–64
is their practical operating range, matching the sub-item's guess. **Evaluation metric** is the
**top-k log-probability drop**: "Top-k-drop(τ) = log p_LM(R | C, Q) − log p_LM(R |
ABLATE(C, v_top-k(τ)), Q)" i.e. original log-prob minus log-prob after ablating the top-k
highest-scoring sources (Definition 2.2). [VERIFIED, arXiv:2409.00729]

**AttriBoT (2411.15102)** speeds up *exact* LOO computation (not the surrogate approach) via three
mechanisms — quoted from the abstract: "AttriBoT uses cached activations to avoid redundant
operations, performs hierarchical attribution to reduce computation, and emulates the behavior of
large target models with smaller proxy models. Taken together, AttriBoT can provide a **>300×
speedup** while remaining more faithful to a target model's LOO error than prior context
attribution methods. This stark increase in performance makes computing context attributions for a
given response **30× faster than generating the response itself**." Mechanism detail: "Approximately
half of the FLOPs needed to naïvely compute LOO attributions are redundant and can be avoided by
caching the attention key and value tensors at each layer... The sum of the LOO attributions for k
contiguous text spans (e.g., sentences in a paragraph or paragraphs in a section) are well-
approximated by a single Leave-k-Out attribution score... The LOO attribution scores for a large
model (e.g., 70B parameters) are well-approximated by smaller models (e.g., 8B parameters) in the
same model family." AttriBoT's own empirical test set is **HotpotQA**: "Figure 1: We empirically
test the assumptions underlying the AttriBoT's underlying methods on examples from Hotpot QA."
[VERIFIED, arXiv:2411.15102]

**Conclusion for n ≤ ~15 sentences.** Both papers exist because exact LOO scales as O(n) forward
passes and gets expensive for *large* contexts (ContextCite's example context has 98 sources;
AttriBoT targets settings where LOO is "prohibitively expensive"). Their own numbers cross over
in our favor at small n: ContextCite still needs ~32 ablations (a linear-regression sample-
complexity floor, not proportional to n) to fit a faithful surrogate even when n is small, i.e.
its 32-ablation floor exceeds `n + 1` exact LOO passes once n ≲ 31; AttriBoT's speedups
(KV-caching ~2×, hierarchical grouping, proxy models) are optimizations *of* LOO for large n and
introduce approximation error (its own reported outlier recall is 90% at half the sources kept,
not 100%) that exact LOO does not have. For our regime (n ≈ 12 sentences per passage), **exact LOO
(n+1 forward passes: 1 baseline + n single-sentence-removed passes) is cheaper than fitting a
≥32-ablation surrogate and introduces no surrogate/proxy-model approximation error** — this is a
reasoned inference from the two papers' own reported operating points, not a direct quote from
either paper recommending exact LOO at small n, so it is marked as an **inference, not a verified
claim**.

## 4c. Metric: comprehensiveness/sufficiency, and pitfalls

**ERASER (1911.03429)** defines the two metrics exactly as specified. Comprehensiveness:

> "following Yu et al. (2019) we define metrics intended to measure the comprehensiveness (were
> all features needed to make a prediction selected?) and sufficiency (do the extracted rationales
> contain enough signal to come to a disposition?) of rationales, respectively. Comprehensiveness.
> To calculate rationale comprehensiveness we create contrast examples (Zaidan et al., 2007): We
> construct a contrast example for xi, x̃i, which is xi with the predicted rationales ri removed...
> Then we consider the predicted probability from the model for the same class once the supporting
> rationales are stripped... comprehensiveness = m(xi)j − m(xi/ri)j. A high score here implies that
> the rationales were indeed influential in the prediction, while a low score suggests that they
> were not."

The AOPC aggregation across bins is also given: "we group tokens into k = 5 bins by grouping them
into the top 1%, 5%, 10%, 20% and 50% of tokens, with respect to the corresponding importance
score." Random-rationale baseline is reported for comparison in all their tables. [VERIFIED,
arXiv:1911.03429] Note: ERASER's precise "sufficiency" formula was not captured in the grepped
excerpt (comprehensiveness dominated the matched context window); it is defined analogously as the
model's confidence using *only* the rationale vs. the full input, per the same section — cite with
the caveat that the exact sufficiency equation number was not independently re-quoted in this pass.

**Pitfall 1 — parametric memory / closed-book answering.** Two verified quantitative results, both
close to but not literally "HotpotQA closed-book":
- Lost in the Middle (2307.03172), multi-document QA (NaturalQuestions-based, not HotpotQA):
  "GPT-3.5-Turbo's performance on the multi-document question task is lower than its performance
  when predicting without any documents (i.e., the closed-book setting; 56.1%)." Full table:
  "GPT-3.5-Turbo | Closed-Book 56.1% | Oracle 88.3%." [VERIFIED, arXiv:2307.03172]
- FanOutQA (2402.14116), a HotpotQA-adjacent multi-hop, multi-document benchmark, reports a
  closed-book setting explicitly: "The closed-book setting requires the model to answer fan-out
  questions without external knowledge, testing its general knowledge... Using only knowledge
  encoded in their parameters, models' loose string accuracy ranged from 0.341 (Claude) to 0.470
  (Mixtral), with none reaching our estimated human baseline of 0.685." [VERIFIED, arXiv:2402.14116]
- **Caveat**: neither is HotpotQA itself reporting a closed-book number; a targeted search for a
  HotpotQA-specific closed-book LLM accuracy figure did not surface one in the time box.
  **UNVERIFIED for HotpotQA specifically** — use the two adjacent-benchmark numbers above as the
  cited evidence for the general phenomenon (non-trivial closed-book accuracy on multi-hop QA,
  i.e. models can partially "cheat" via parametric memory), with the caveat stated.

**Pitfall 2 — EM vs. log-prob disagreement.** Not independently re-verified with a dedicated
citation in this pass; flagged as a known, common empirical observation (a model can produce the
exact-match-correct string while assigning it low probability, or vice versa near a decision
boundary) rather than a cited claim. **UNVERIFIED** as a standalone citation; treat as a
methodological risk to check empirically rather than assert from literature.

**Pitfall 3 — Referential Dangling, Hu et al. 2026 (arXiv:2608.04569, NOT 2609.xxxx — corrected
from the 2026 guess in the prompt).** Full quote: "independent selection can split dependent
evidence pairs, retaining one member while deleting the other. When the retained text span
contains an answer but the deleted span defines the entity needed to interpret it, we call the
result referential dangling. At compression ratio 0.30, Beaver, which ranks coherent chunks using
Qwen3-0.6B embeddings, leaves the answer path incomplete in 34 to 54% of bridge examples across
three multi-hop question answering (QA) datasets [HotpotQA, 2WikiMultiHopQA, MuSiQue]." Fix
result: "reinserting the missing supporting paragraph and offsetting its tokens by removing
paragraphs not annotated as supporting the answer improves accuracy by 29 to 34 points (p <
10⁻⁴), recovering at least 88% of the gap." [VERIFIED, arXiv:2608.04569] **Relevance to LOO
ablation as ground truth**: this is a direct warning that *independent* per-sentence ablation
(dropping one sentence at a time, our exact-LOO design) can silently break an inference chain when
a "dependent" sentence (e.g., the bridge-defining sentence) is removed while its dependent (the
answer sentence) is kept — i.e. LOO importance for a single sentence can be confounded by whether
its *paired* bridge sentence is present. This should be reported as a limitation of LOO-based
ground truth on bridge-type questions specifically.

**Pitfall 4 — teacher-forcing tokenization / leading-space-after-assistant-header.** HF's own chat
templating documentation explains why `add_generation_prompt=True` matters: "This argument adds
tokens to the end of the chat that indicate the start of an `assistant` response... if you don't
include these tokens, the model may get confused and do something strange, like continuing the
user's message instead of replying to it!" [VERIFIED quote, but this documents the *chat-template
boundary* issue, not literally "leading space" tokenization]. A **precise citation for the specific
"leading space after the assistant header" tokenization pitfall** (a known BPE artifact where
`" answer"` and `"answer"` tokenize differently depending on whether a space precedes the
teacher-forced continuation) was **not found as an exact quote** in the time box — searches
surfaced adjacent-but-not-identical material (HF chat-templating docs, a "Token Healing" blog post
on trailing-space artifacts). **UNVERIFIED** as a directly-quoted claim; recommend citing this as
an internal implementation check (verify tokenizer round-trip on the exact teacher-forced string)
rather than an external citation.

## 4e. Significance testing and comparison-table spec

**Koehn 2004, "Statistical Significance Tests for Machine Translation Evaluation" (EMNLP 2004,
ACL Anthology W04-3250).** Quote: "If two translation systems differ in performance on a test set,
can we trust that this indicates a difference in true system quality? To answer this question, we
describe bootstrap resampling methods to compute statistical significance of test results... Even
for small test sizes of only 300 sentences, our methods may give us assurances that test result
differences are real." Paired bootstrap section: "As stated earlier, the value of scoring metrics
comes from being able to compare the quality of different translation systems. Typically, we want
to compare two systems. We translate the same test set with the two systems, and measure the
translation quality using [a metric], with some difference in score. Can we conclude that the
better scoring system is truly better?" [VERIFIED, ACL Anthology W04-3250 / EMNLP 2004]

**Dror et al. 2018 (1809.01448), "The Hitchhiker's Guide to Testing Statistical Significance in
Natural Language Processing".** Quote: "on the same dataset, one should use the paired version of
the statistical significance test (such as the matched-pair t-test)." [VERIFIED, arXiv:1809.01448]
This directly supports using a **paired** test (paired bootstrap or McNemar) rather than an
unpaired test, since the same sentence-ablation is applied to the same passage/model across
conditions.

**McNemar's test** is the standard paired test for paired *binary* outcomes (e.g.,
correct/incorrect per example before vs. after ablating a sentence) — used here for the
"answer flips correct→incorrect" comparison; not independently re-quoted from a primary source in
this pass, but it is the standard, well-established choice for 2×2 paired binary contingency data
and is not a contested claim.

### Per-sentence comparison-table spec

For each (example, sentence) pair, record one row:

| example_id | sentence_id (S1..Sn) | is_gold_supporting (bool, from supporting_facts /
paragraph_support_idx) | baseline_logprob (full context) | ablated_logprob (sentence removed) |
delta_logprob = ablated − baseline | baseline_answer_correct (bool, EM) | ablated_answer_correct
(bool, EM) | answer_flip (bool) | median_abs_delta_nongold (per-example, computed over
non-gold-supporting sentences only) | breaks_performance (bool, see definition below) |
elicited_keep (bool, from Q2's LLM-elicitation "keep" set) | agree_with_LOO (bool: elicited_keep ==
is_LOO_important) |

Aggregate significance test: **paired bootstrap (Koehn 2004)** or **McNemar** on
`answer_flip`/`agree_with_LOO` across examples, comparing e.g. the elicitation method's precision/
recall against the LOO ground truth, or comparing two elicitation variants (Q2's task-agnostic vs.
query-aware) against each other — always paired at the example level per Dror et al.'s
recommendation.

### "Breaks performance" definition (fixed before looking at results)

A sentence **breaks performance** when removing it causes **either**:
1. `answer_flip = True` (the model's answer changes from correct to incorrect under exact match),
   **OR**
2. `|delta_logprob| > 2 × median(|delta_logprob| over non-gold-supporting sentences in the same
   example)` — i.e. the log-probability shift from removing this sentence is more than twice the
   typical (median) shift from removing an irrelevant sentence in the same passage.

This threshold is stated here, before any results are inspected, per the sub-item's requirement,
and uses a **per-example** non-gold median (not a global constant) so it adapts to each passage's
own noise floor.
