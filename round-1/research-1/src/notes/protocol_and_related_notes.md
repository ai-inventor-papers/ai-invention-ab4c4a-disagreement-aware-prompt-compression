## LongBench (arXiv 2308.14508 v2; code github.com/THUDM/LongBench)
- Multi-Doc QA built from HotpotQA / 2WikiMultihopQA / MuSiQue, metric F1, 200 examples each, avg len 9,151 / 4,887 / 11,214 words.
  > "The English test samples are built from three Wikipedia-based multi-hop QA datasets: HotpotQA (Yang et al., 2018), 2WikiMultihopQA (Ho et al., 2020), and MuSiQue (Trivedi et al., 2022)."  (PDF, Sec. 3 Multi-Doc QA)
  > "HotpotQA 2-1 Wikipedia 9,151 F1 English 200 / 2WikiMultihopQA 2-2 Wikipedia 4,887 F1 English 200 / MuSiQue 2-3 Wikipedia 11,214 F1 English 200" (PDF Table 1)
  > "these passages are randomly ordered to form the multi-document context" (PDF Sec. 3)
- metrics.py: normalize_answer = lower, remove punctuation, remove articles (a|an|the), whitespace fix; qa_f1_score = token-level F1 on normalized whitespace-split tokens; eval.py takes max over ground truths; scores are round(100*mean, 2).
  > "def normalize_answer(s): \"\"\"Lower text and remove punctuation, articles and extra whitespace.\"\"\"" (LongBench/metrics.py)
  > "def qa_f1_score(prediction, ground_truth, **kwargs): normalized_prediction = normalize_answer(prediction) normalized_ground_truth = normalize_answer(ground_truth) prediction_tokens = normalized_prediction.split() ground_truth_tokens = normalized_ground_truth.split() return f1_score(prediction_tokens, ground_truth_tokens)" (LongBench/metrics.py)
  > "for ground_truth in ground_truths: score = max(score, dataset2metric[dataset](prediction, ground_truth, all_classes=all_classes))" (LongBench/eval.py, scorer)
  > dataset2metric: "hotpotqa": qa_f1_score, "2wikimqa": qa_f1_score, "musique": qa_f1_score (LongBench/eval.py)
- Prompt template (config/dataset2prompt.json), identical for hotpotqa/2wikimqa/musique:
  > "Answer the question based on the given passages. Only give me the answer and do not output any other words.\n\nThe following are given passages.\n{context}\n\nAnswer the question based on the given passages. Only give me the answer and do not output any other words.\n\nQuestion: {input}\nAnswer:"
- dataset2maxlen.json: "hotpotqa": 32, "2wikimqa": 32, "musique": 32 (max new tokens).
- No EM in LongBench (F1 only); EM is the SQuAD/HotpotQA companion metric using the same normalize_answer.

## FrugalPrompt (arXiv 2510.16439 v5, Raiyan, Ishmam, Al Imran, Moni; code Starscream-11813/Frugal-ICL; site frugalprompt.github.io)
  > "Leveraging two state-of-the-art token attribution methods, GlobEnc and DecompX, we assign salience scores to every token in an input sequence, rank them to retain the top-k% tokens, and obtain a sparse frugalized prompt."
  > "saliency scores are generated by state-of-the-art token attribution methods (Modarressi et al., 2022, 2023) applied to a single 110M-parameter BERT model"
  > "Across four NLP tasks, a 20% prompt reduction preserves performance for most models with negligible parameter overhead."
  > "Inputs longer than the encoder's 512-token window are scored via sentence-level chunking, as detailed in Appendix C."
  > "We define a task-specific scoring function φτ ∈ {GlobEnc, DecompX} for a task τ"
  > "we retain only the top p = ⌈k/100 · n⌉ tokens, where k is the retention percentage"
  - Tasks: CLS (IMDb sentiment), SUM, QA (CosmosQA), RSN (GSM8k); Table shows Llama-3 8B GlobEnc k=80: CLS acc 0.942 vs 0.949 full; GSM8K pass@1 drops 0.786 -> 0.500 at 80%.
  - Not: question-conditioned; not multi-hop long-context; encoder is task-specific (fine-tuned BERT classifier), so scores are task-label attributions, not answer-relevance.

## MIST (arXiv 2608.31066 v1, 31 Aug 2026; Zhao, He, Zheng, Chen) "Every Token Leaves a Ripple in the Stream of Thought"
  > "MIST (Model-Internal Saliency for Token-level CoT compression), which defines token importance along two complementary axes: necessity, the drop in answer likelihood when a token's internal contribution is removed, and sufficiency, the gain in answer likelihood when that contribution alone is provided."
  > "(a) necessity measures the decrease in answer likelihood when the token's residual contribution is removed; (b) sufficiency measures the increase in answer likelihood when that contribution is patched into a no-chain forward pass." (Fig. 1 caption)
  > "Results on 100 MATH reasoning chains with Qwen2.5-1.5B-Instruct." (Fig. 2 caption)  — note: uses the same 1.5B model as our target
  > "Necessity and sufficiency induce weakly correlated rankings (mean Spearman ρ = −0.07 and top-30% overlap 0.28)"
  - Scope: CoT (reasoning-token) compression for model adaptation / training-data pruning, not input-context compression; requires answer likelihood (needs the gold answer at scoring time) and residual-stream patching.

## Referential Dangling (arXiv 2608.04569 v1; Hu, Li, Fu, Zou, Tang, Li, Cao, Huang; code https://cslikai.cn/Referential-Dangling)
  > "independent selection can split dependent evidence pairs, retaining one member while deleting the other. When retained text contains an answer but deleted text defines the entity needed to interpret it, we call the result referential dangling."
  > "We define r = |C̃|/|C| and use binary search to reach each target ratio."  (Sec. 4.1) — kept-fraction ratio definition, same convention as our 0.3/0.5/0.7
  > "HotpotQA and 2WikiMultiHopQA use contexts of about 40 paragraphs and 5.7k tokens, formed by mixing annotated supporting paragraphs with sampled distractors; MuSiQue uses its native 20-paragraph contexts."
  > "The comparison includes six hard compressors that assign importance using different signals: embedding similarity with Beaver (Hu et al. 2026), syntactic parse structure with PartPrompt (Mao et al. 2025), self-information with Selective-Context (Li et al. 2023), a learned token classifier with LLMLingua-2 (Pan et al. 2024), perplexity with LongLLMLingua (Jiang et al. 2024), and importance derived from attention with DAC (Zhao et al. 2025)."
  > "all six compressors tested exhibit dangling at rates from 32 to 60%"
  > Table 2 first row (dangling rate, HotpotQA bridge n=184, r=0.30): values printed "0.36 ... 0.23 ... 0.30 ... 0.29 ... 0.32" for Beaver row; the header row of dangling rates was cut in the grep output — UNVERIFIED per-compressor rates beyond the 32–60% range statement.
  > "On dangling examples evaluated with Qwen3-8B, this intervention improves accuracy by 29 to 34 points without increasing the token budget"
  > "this automatic restoration improves accuracy by 4.7 points while changing the compression ratio only from 0.30 to 0.31."
  - Metric: accuracy (Qwen3-8B / Qwen3-4B / GPT-5.5 / GLM-5.2 as answer models), not F1.
